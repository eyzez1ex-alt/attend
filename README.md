# RU here? — نظام إدارة الحضور

واجهة عربية RTL لإدارة الحضور والإجازات، مبنية بـ React وTypeScript وVite. تستخدم المصادقة عبر Firebase Authentication عند توفر الإعداد، وتضم مخططاً علائقياً جاهزاً لـ Firebase SQL Connect/PostgreSQL. لا تحتوي على سجلات تجريبية.

## التشغيل المحلي

```sh
npm install
npm run dev
```

ملف `.env.local` موجود محلياً ومُستثنى من Git. عند إعداد نسخة أخرى، انسخ `.env.example` إليه وأدخل إعداد تطبيق الويب من Firebase Console. افتح عنوان Vite المحلي الظاهر في الطرفية. أنشئ نسخة إنتاجية باستخدام `npm run build`، أو عاينها عبر `npm run preview`.

## الصفحات

- تسجيل الدخول: يستخدم Firebase Authentication بالبريد وكلمة المرور، ويحتاج الحساب إلى دور موثّق في Firebase claims. لا توجد حسابات أو كلمات مرور افتراضية.
- المشرف: نظرة عامة، الموظفون، الحضور، الموقع، الإجازات، العطلات المصرية، التقارير، وصلاحيات المشرفين.
- الموظف: الرئيسية، سجل الحضور، الإحصائيات، الإجازات، والملف الشخصي والجهاز.

يمكن التنقل بين مساحتي المشرف والموظف لمعاينة التصميم فقط. الحساب المحدد الوحيد لمنح صلاحية المشرف هو `yusufgibrel3@gmail.com`. إخفاء عناصر الواجهة ليس حماية؛ يجب أن يثبت الخادم هوية المالك عند كل منح أو سحب.

تقرير الحضور الشهري يتضمن واجهة تنزيل Excel-compatible CSV وحفظ PDF وأرشيفاً للمشرفين. الإنشاء التلقائي بعد إغلاق الشهر وإتاحته للمشرفين يتطلب خدمة خلفية مجدولة؛ المتصفح وحده لا ينفذ ذلك عند إغلاق التطبيق.

## Firebase والبيانات

إعداد Firebase Web App موجود في `.env.local` المحلي، وتُنشأ جلسات البريد وكلمة المرور عبر Firebase Authentication. فعّل Email/Password في Firebase Console وأضف نطاق التطبيق ضمن النطاقات المصرح بها. يجب أن تتضمن مطالبات الحساب الموثّقة `role`، وأن يتضمن حساب الموظف `employeeCode` المطابق لرمز الدخول.

مخطط الجداول في `dataconnect/schema/schema.gql` مستوحى من بنية الموظفين والأجهزة والحضور والإجازات وإعدادات العمل وسجل الإدارة، مع إضافة العطلات المصرية وأيام الراحة وأرشيف التقارير. كل القوائم تبدأ فارغة. لا تُكتب سجلات الحضور أو الإجازات أو العطلات حتى إنشاء خدمة SQL Connect والعمليات الموثوقة. راجع `dataconnect/README.md` قبل إعداد Cloud SQL والنشر.

عقود الخدمات في `src/services/api.ts` توضح ما تستخدمه الواجهة؛ المصادقة متصلة، بينما عمليات البيانات تنتظر إعداد خدمة SQL Connect وعملياتها. لا يتصل التطبيق بقاعدة بيانات حتى يحدد اسم الخدمة والمنطقة والموصل في `.env.local`.

قواعد أيام العمل في `src/utils/attendance.ts` تستثني العطلات الواردة من المصدر، وأيام الراحة المحددة من المؤسسة، والإجازات المعتمدة. لا توجد تواريخ عطلات أو أيام راحة افتراضية. يُحتسب يوم الحضور المكتمل فقط عندما يحتوي السجل على وقتي تسجيل الحضور والانصراف مع حالة «حاضر» أو «متأخر».
